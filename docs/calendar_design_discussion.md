# 設計検討：計画と実績を一体で見るトレーニングカレンダー

このドキュメントは、メインテーブルを「実績ログ」から「計画と実績を一体で見るトレーニングカレンダー」へ進化させるための設計議論をまとめたもの。一度読んで作戦を立てるための叩き台。

---

## 1. 出発点：to-beデータの発見

ユーザーから共有された理想形（to-be）データは 6/1〜8/10 の **未来のスケジュールを含む計画表** だった。
これによりアプリの位置づけが変わる：

- **as-is**：実績ログ（走った記録を残す）
- **to-be**：計画と実績を一体で見るトレーニングカレンダー（PDCAの実体）

### to-beデータの列構成

```
date / dow / menu / notes / section / locate / shoes
```

### to-beデータの構造的特徴

1. **section列が新登場** — WU / メイン / CD の区分（設計上の session_type に対応）
2. **1日が複数行に分かれる** — 走る日は WU/メイン/CD で複数行、ランオフ日は section 空欄の1行
3. **notes列** — 現行の memo に相当（ただし「狙い・指示」のニュアンス）
4. **未来の予定が含まれる** — 実績だけでなく計画行が並ぶ

### 6/6の例（原データ）

```
6/6  自然収束ジョグ  notes...  WU   自宅〜多摩川
                              メイン 多摩川       NeoZen
                              CD    多摩川〜自宅
6/7  ランオフ      notes...                       ← section空
```

---

## 2. 確定した設計判断

### 2.1 階層構造は却下 → 1行1セクション

- 親行＋子行の階層表示は**却下**
- **1行＝1セクション**（WU/メイン/CD/ランオフ それぞれ独立した1行）
- 理由：実装も表示も複雑になる。既存のフラットな sessions テーブルと相性が良い。現行の同日グルーピング表示がそのまま使える

### 1行1セクションでの6/6表現

```
6/6  WU    自然収束ジョグ(notes)  自宅〜多摩川   -
6/6  メイン  自然収束ジョグ(notes)  多摩川        NeoZen
6/6  CD    自然収束ジョグ(notes)  多摩川〜自宅   -
6/7  ―     ランオフ(notes)        -            -   ← sectionなし1行
```

ランオフ日は section 空の1行。走る日は WU/メイン/CD で複数行。同日グルーピングで1日にまとまる。

### 2.2 ゴール

**計画と実績を一体で見るトレーニングカレンダー**

### 2.3 主眼（2点）

1. 予定と実績の紐付け
2. データのインポート（自動／手動）

---

## 3. 予定と実績の紐付け

### 3.1 紐付け方式：同居型（案①）を採用方針

**1行が「予定」と「実績」の両方を持つ**

```
1行 = 6/6 メイン
  ├ 予定パート：planned_menu, section, locate, shoes候補, notes
  └ 実績パート：distance, pace, HR, ラップ...（走ったら埋まる）
```

採用理由：
1. 「1行＝1トレーニング」が直感的。カレンダーとして、その枠が「予定だけ（未来）」「予定＋実績（完了）」「予定なし実績だけ（飛び込み）」を1行で表現できる
2. 既存スキーマ（planned_menu と menu が既にある）の自然な拡張
3. 紐付けロジックが「どの行に実績を入れるか」だけで済む

（対する案②＝予定行と実績行を別レコードで持ち表示時に重ねる方式は、リンク管理が複雑になるため非採用方針）

### 3.2 1行の状態遷移（同居型）

```
【未来の予定】   planned_menu=構造再起動, 実績パート=空
      ↓ その日が来て走る
【実績を紐付け】 planned_menu=構造再起動, menu=実走内容, distance/HR=Suunto実績
      ↓ または予定通りでなかった
【予定と乖離】   planned_menu=構造再起動, menu=ランオフ（走らなかった理由をnotesに）
```

### 3.3 紐付けのトリガー：まず手動、将来自動マッチ（確定）

**運用フロー：**

```
① 計画を作る（未来の予定行が並ぶ）
   6/13 WU   構造再起動  自宅〜砧公園  -          ← 実績パート空
   6/13 メイン 構造再起動  砧岡本      Boston13    ← 実績パート空
   6/13 CD   構造再起動  砧公園〜自宅  -          ← 実績パート空

② 6/13に実際走る → Suuntoから3セッション取り込み

③ 取り込み画面で紐付け（手動）
   「この実績(3.3km)は → 6/13メインの予定行へ」を選ぶ
   → メインの予定行に distance/HR/ラップ... が流し込まれる

④ 結果
   6/13 メイン 構造再起動(予定) / 砧岡本2周(実績) 3.3km 5:59/km ...
        → 予定と実績が1行で並ぶ
```

**将来（Phase B）**：③の「どの予定行へ」を 日付＋section＋時刻順 で自動提案 → ユーザーは確認するだけ。

## 4. 計画（予定行）の作り方

### 4.1 方針：TSV貼り付け／ファイルでインポート（推奨）

ユーザーは計画作成の好みは「特になし」。既存資産を最大活用する形を推奨。

- ユーザーは既にChatGPTと TSV形式（date/dow/menu/notes/section/locate/shoes）で計画を作る運用がある
- 11章のAIメニュー生成もTSV返却で設計済み → **同じインポート機構を計画にも使える**
- 1日ずつUI手入力は3ヶ月分だと大変

→ **計画インポート = TSV貼り付け or ファイル**。AIメニュー生成（11章）の出力TSVも同じインポートに通せる。インポート機構が1つで済む。

---

## 5. 必要な実装要素（4つ）

1. **スキーマ拡張**
   - sessions に `notes`（既存memoと統合 or 別）、`section`(WU/main/CD) を整理
   - 計画専用フラグ／planned系の整理
2. **計画TSVインポート**
   - date/dow/menu/notes/section/locate/shoes を取り込み、予定行として登録
3. **テーブル表示**
   - 計画行（実績なし＝未来）と実績付き行を一体表示
   - 列順を to-be に合わせる（date/dow/menu/notes/section/locate/shoes）
4. **実績紐付け**
   - Suunto取り込み時に予定行を選んで実績を流し込む（手動 → 将来自動）

## 6. 未解決の論点（次に詰める）

### 6.1 【要確認】menu / notes / planned_menu の役割分担

同居型で1行に予定と実績を持たせる時の、各フィールドの役割。提案中の整理：

| フィールド | 役割 | 性質 |
|---|---|---|
| `planned_menu` | 計画のメニュー名（例：構造再起動） | 計画時に設定・不変 |
| `menu` | 実績のメニュー（実際やったこと） | 走った後に記入／実績 |
| `notes` | 計画時の狙い・指示（例：登りで頑張らない…） | 計画時に設定・**不変**。実績が来ても残る＝評価軸として機能 |
| 実績データ | distance/HR/ラップ等 | Suunto由来 |

ポイント：
- notes（狙い・指示）は実績が来てもそのまま残り、**評価軸として機能する**
- これは12章のフェーズレポート常駐プロンプトとも噛み合う（AI評価時に「狙い」を踏まえられる）

→ **この3フィールドの役割分担で合意できるか？ が次の確認事項。合意できればスキーマ設計に入る。**

### 6.2 section と既存 session_type の関係

- 現行スキーマには既に `session_type`（warmup/main/cooldown/NULL）がある
- to-beの `section`（WU/メイン/CD）はこれに対応
- → section列はsession_typeをそのまま使えばよいか、表示名（WU/メイン/CD）をどうするか

### 6.3 既存memoとnotesの統合

- 現行 `memo`（練習内容メモ）と to-beの `notes`（狙い・指示）は同じか別か
- 統合するか、notesを新設するか

### 6.4 未来日の表示

- 実績のない未来の計画行を、テーブルでどう見せるか（色・スタイルで「予定」と分かるように？）
- 起動時の表示月は「最新の実績がある月」か「今日を含む月」か

## 7. 全体像（現時点の合意イメージ）

```
トレーニングカレンダー（1行1セクション・同居型）

[計画フェーズ]
  TSVインポート or AIメニュー生成（11章）
       ↓
  予定行が並ぶ（planned_menu, notes, section, locate, shoes候補）
  実績パートは空。未来日として表示

[実行フェーズ]
  Suuntoで走る → 生JSON取り込み（15章）
       ↓
  取り込み画面で「どの予定行に紐づけるか」を手動選択（将来自動）
       ↓
  予定行に実績（distance/HR/ラップ）が流し込まれる

[評価フェーズ]
  1行に予定（notes＝狙い）と実績が並ぶ
       ↓
  AI評価（5章）：notesを評価軸に、実績を評価
  フェーズレポート（12章）も評価軸として常駐
       ↓
  「予定通りやれたか」「狙い通りのフォームか」をPDCAで回す
```
