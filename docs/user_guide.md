# Suunto Run Tracker 使い方ガイド

2026-06-12版 ／ 対応バージョン：Phase 2 第1スライス（計画TSVインポート）まで

このアプリは「走った記録を残すツール」ではなく、**計画に対する進捗評価（PDCA）を回すためのトレーニングカレンダー**です。計画（slot）と実績（result）を同じテーブルで一体に眺め、将来はAI評価までを一気通貫で回します。本ガイドは現時点で動く機能の操作方法と、データの約束事をまとめたものです。

---

## 1. 起動

ターミナルでプロジェクトフォルダ（`~/Documents/run/suunto-run-tracker`）に移動し、`npm run dev` を実行します。nodemonがサーバー（server/index.js）を起動・監視し、コードが変わると自動再起動します。ブラウザで http://localhost:3000 を開いてください。

起動時に表示されるのは**今日を含む月**です（その月にデータが無い場合は、データのある最新月が開きます）。

## 2. 画面の構成

画面上部にヘッダー（タイトル／↑取り込み／＋追加／⚙設定）、その下に月ナビゲーション（◀ ▶ で前月・次月、年月表示クリックでカレンダーピッカー）、タイプフィルタと検索ボックス、一括操作バー（全選択／Claude一括評価／GPT一括評価／エクスポート）、そしてメインのカレンダーテーブルが並びます。フッターには表示中の月の件数・月間距離・月間TRIMPが常時表示されます。

## 3. 行の読み方（いちばん大事な節）

テーブルの**1行は1つのトレーニング枠（slot）**です。走る日はWU／メイン／CDで複数行、ランオフ日は1行。同じ日付の行はグルーピングされ、日付は先頭行にだけ表示されます。

| 表示 | 意味 |
|---|---|
| 🏃 | ランニングの枠（slot_type=run）。実績数値があれば同じ行に表示 |
| 💤 | ランオフの枠（slot_type=rest）。例外的に距離を持つ行が3件あります（「ランオフ予定→実際は少し走った」過去データ） |
| 📅＋グレー行 | **計画行（status=planned）**。まだ実績が無い予定。実績数値列は空欄 |
| WU / M / CD バッジ | その枠のセクション（ウォームアップ／メイン／クールダウン） |
| 🔒 | AI評価がロック済み（確定済み）であることを示す |

行の左側の数値列（距離・タイム・ペース・HR・標高・kcal・TRIMP・バイオメカ各列）は**実績（result）由来＝機械由来の計測値**で、手で編集できません。メニュー・メモ・場所・シューズ・感想は**計画／手動由来**で、インライン編集できます。

表示単位の規約：距離=km、HR=bpm（整数）、Cadence=spm（整数）、歩幅=m（小数2桁）、VO=cm（小数1桁）、GCB=%（小数1桁）、GC=ms。

## 4. 月ナビ・フィルタ・検索・ソート

◀ ▶ で月を移動します。計画だけの未来月（現在なら7月・8月）にも移動でき、その場合フッターの月間距離は0.0kmになります（計画は集計に数えない、後述）。

タイプフィルタ（ランニング／ランオフ／手動記録）はボタンのON/OFFで行を絞り込みます。計画行にも効きます。検索ボックスはメニュー・メモ・感想・AI評価を対象にしたフリーテキスト絞り込みです。列ヘッダーのクリックでソートできます（既定は日付昇順）。

## 5. 計画TSVインポート（新機能）

ChatGPT等で作った計画表を貼り付けて、予定行として一括登録します。

**フォーマット**：タブ区切り・1行目はヘッダー `date dow menu notes section locate shoes` 固定。日付は `6/13` 形式（年は画面の年セレクタで指定、既定は今年。月が小さくなったら自動で翌年扱い）。走る日はWU／メイン／CDで複数行に分け、**2行目以降は date・dow・menu・notes を空欄**にします（先頭行から継承されます）。ランオフ日はsection空欄の1行です。

**操作**：「計画インポート」を開く → TSVを貼り付け → プレビューで内容を確認 → 取込実行。プレビューには期間・日数・枠の内訳・警告が表示されます。警告は2種類で、いずれも取込自体は可能です：

- 曜日不一致：日付から計算した曜日とdow列が合わない行（計画表の作成ミス検知用）
- 既存slotあり：その日付に既にデータがある場合。**上書きはされず、計画行が追加されます**

**取り消し**：取込直後の画面に「この取込を取り消す」ボタンがあり、今回挿入した計画行だけを一括削除できます（実績行には絶対に触れない設計です）。ページを再読み込みすると取り消しボタンは消えるので、その場で判断してください。

**計画と実績がぶつかったら**：たとえば6/7は計画「ランオフ」に対して実績3走行が並び、1日4行になります。これは仕様です — 計画と現実の乖離がそのまま見えるのがこのアプリの本質で、隠しません。実績を計画行に紐付ける機能はPhase 2第2スライスで実装予定です。

## 6. Suunto実績の取り込み

Suuntoアプリからエクスポートした**生JSON**を「↑取り込み」からドラッグ＆ドロップします。サーバー内蔵のパーサーが単位変換（m→km、bps→bpm、rps→spm×2、歩幅はSpeed÷Cadenceで再計算、等）を行って登録します。生JSONファイルは data/suunto_raw/ に保管され、これが**真実の源**です — DBの数値はそこからの導出キャッシュで、いつでも再構築できます。

同日にWU／メイン／CDを時計で別々に記録した場合は、別々の枠として取り込まれ、同日グルーピングで1日にまとまります。

## 7. 編集

編集できるセルをクリックするとインライン編集になり、確定でSQLiteに即保存されます。メニュー・場所・シューズには過去入力からのサジェストが出ます。シューズ欄はフリーテキストです（「Boston13 / Novablast5」のような候補併記もそのまま書けます。プルダウン化は将来）。

感想欄は将来のAI評価で必ず送信される重要フィールドなので、走った日の主観（脚の感覚・呼吸・フォームの気づき）を書く習慣をつけると、Phase 3以降の評価の質が上がります。

## 8. 詳細ドロワー

行のアイコンをクリックすると、画面右に詳細ドロワー（幅40%）が開きます。セッションのサマリー、ラップテーブル、Chart.jsのグラフ（HR／ペース等）が見られます。ラップはDBに保存せず、生JSONからその場でパースして表示しています。

ドロワーを開いたまま背面のテーブルをスクロール・クリックできます（マスクは装飾で、操作を遮りません）。別の行のアイコンをクリックすると、ドロワーの中身がその日に切り替わります。一覧で流れを追いながら特定の日を凝視する、マスター・ディテール同時閲覧のための意図的な設計です。

## 9. フェーズ管理とまとめバー

練習期間を「フェーズ」（回復期・ピーク期など）として登録でき、テーブル内のフェーズ境界に**まとめバー**（回数／距離／TRIMP合計／平均）が表示されます。月間集計・フェーズまとめとも **計画行（planned）は数えません**。実績だけが集計されます。

## 10. AI評価とロック

各行にClaude評価・GPT評価の欄があります。役割分担は、Claude=客観コーチ（事実と改善点、褒めない）、GPT=寄り添いコーチ（感情サポート）。**評価APIへの接続はPhase 3予定で、現在の評価ボタンはUIのみ**です。過去のスプレッドシート時代のGPTコメント172件は移行済みで、すべてロック保護されています。

ロック機構：評価欄の「確定」でロックされ、🔒が付いてAIボタンが無効化されます。「解除」（確認ダイアログあり）で個別に外せます。サーバー側でもロック中の評価リクエストは403で弾く二重ガードです。

## 11. エクスポート

一括操作バーの「エクスポート」から、表示中のデータをTSVまたはMarkdownで書き出せます。AI（ChatGPT等）に範囲を渡して相談する際の手土産に使えます。

## 12. バックアップ

`npm run backup` で、**手で入力したデータ**（slots／evaluations／phases／reports／shoes）を data/backup/ にJSONで保存します（30世代まで自動管理）。実績数値（results）は生JSONから再構築できるため対象外です。**週1回、および計画インポートのような一括操作の前**に流す運用を推奨します。復元は手動です（手順はserver/scripts/backup.js冒頭のコメントに記載）。

## 13. データの約束事（背景にある設計）

覚えておくと挙動が腑に落ちる3つの原則：

1. **slot（枠）とresult（計測）は別物**。枠は計画でも実績でもあり、計測は機械からしか来ない。だからグレーの計画行に数値は入らないし、数値セルは編集できない
2. **生JSONが真実の源**。DBは導出キャッシュ。変換ロジックに修正が入っても、生データから再計算できる
3. **statusの4状態**：planned（予定）→ done（完了）／skipped（流れた）、計画なしで走れば unplanned。現在のデータでは、移行した過去280件はすべてdone、TSVで入れた109件はすべてplannedです

## 14. 現在地と今後の機能

| 状態 | 機能 |
|---|---|
| 動いています | カレンダーテーブル一式、Suunto生JSON取り込み、計画TSVインポート、編集、ドロワー、フェーズ管理、ロック、エクスポート、バックアップ |
| 次（Phase 2 第2スライス） | **実績の紐付け**：取り込み時に「どの計画枠の実績か」を選んで接続、計画行が実績で埋まる |
| Phase 3 | AI評価のAPI接続（構造化差分＋常駐フェーズレポートを評価軸に） |
| Phase 3.5 | AIメニュー生成（TSVを返させて計画インポートにそのまま通す） |
| Phase 4 | Suunto/Runalyze APIによる自動取得、自動マッチング、トレンドビュー |

## 15. 困ったとき

計画インポートを間違えた → 直後なら「この取込を取り消す」。画面を閉じてしまった場合は、対象が planned かつ tsv_import 由来に限定されるため、次の取込前にバックアップから状況確認のうえ手動削除（相談してください）。

表示がおかしい・データが消えたように見える → まずタイプフィルタと検索ボックスが絞り込んでいないか確認。次に月ナビの位置を確認（起動月の仕様は1章）。

データベースを壊した気がする → 旧テーブル（sessions）はソーク期間中そのまま残っており、data/backup/ に世代バックアップ、data/suunto_raw/ に生データがあります。三重の保険があるので、慌てず最後の正常時点を特定してから復旧します。
